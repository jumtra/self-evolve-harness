# コードレビュー

変更されたコードを以下の観点でレビューする。

## レビュー観点

1. **YAGNI / KISS / DRY 準拠**: 不要な抽象化、過度な複雑さ、重複がないか
2. **アーキテクチャ準拠**: `.claude/rules/architecture.md` の依存方向・配置規約・禁止パターンに違反がないか（同ファイルが無い＝フラット構造なら本項はスキップ）
3. **型安全性**: 型ヒントの欠落、`Any` の不必要な使用がないか
4. **テスト**: 変更に対応するテストがあるか、テストが十分か。加えて `.claude/rules/testing.md` の
   DAMP 準拠を検査する（ヘルパー/ファクトリ/共有 setup/基底クラスに入力値やアサーションが隠れていないか、
   ループでアサーションを回していないか、テスト名に「対象・状況・期待結果」が入っているか）。
   **テスト1つを切り出して読んで入力値・操作・期待値が見えないものは Critical**
5. **Fail Fast**: 不正な入力を早期に検出しているか
6. **可読性**: 命名、関数長、複雑度が適切か

## 出力形式

問題ごとに以下を報告:

- **重要度**: Critical / Warning / Info
- **場所**: `ファイル:行番号`
- **問題**: 何が問題か
- **修正案**: どう直すべきか

Critical → Warning → Info の順に列挙する。

## 自律実行時の判断

自律実行フェーズ（brainstorm 承認後）で呼ばれた場合:

- **Critical 指摘**: 呼び出し元に修正が必要な箇所と修正案を返す。呼び出し元が修正を実行する
- **構造的リファクタリング**: 「refactorer エージェントへの委譲を推奨」と明記する
- **Warning / Info**: 報告のみ。自律実行を止めない
