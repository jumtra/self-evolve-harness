# ワークフロー規約

## ブランチ命名

- `feat/<topic>`: 新機能
- `fix/<topic>`: バグ修正
- `data/<topic>`: データ追加・変更
- `refactor/<topic>`: リファクタリング

## コミットメッセージ

- 日本語可
- 動詞始まり
- 件名50文字以内
- 本文は必要に応じて空行の後に追加
- 動作未検証のコミットは正直に `WIP:` プレフィクスを使う。`fix:` や `feat:` は検証済みのみ

## PR

- `.github/pull_request_template.md` 厳守
- セクション: 概要（必須）/ 変更内容（必須）/ 備考（任意）/ 関連Issue（任意）
- `/self-review` を PR 作成前に実施
- CI が通ることを確認してから PR 作成

## Evidence-Before-Assertion（証拠ファースト）

「修正完了」「テスト通過」「問題なし」を主張する前に、必ず実行結果を提示する:

- CI の実行結果を示してからCI通過を主張する
- テスト結果の出力を示してからテスト通過を主張する
- 動作確認のログやスクリーンショットを示してから動作確認済みを主張する

証拠なき主張は信頼できない。

## マージ

- squash merge 推奨
- ベースブランチは `main`

## 並列ディスパッチ

独立した作業は Agent ツールを**1メッセージで複数呼び出し**、並列実行する（1メッセージ1
エージェントを繰り返すと直列になる）:

- 実装計画の独立タスク → `implementer` を wave 単位で並列起動
- レビュー + テスト生成 → `reviewer` と `test-writer` を同時起動
- 複数モジュールの偵察 → Explore エージェントを並列ディスパッチ

**同一 wave に入れてよい条件**（すべて満たすとき）: 所有ファイル集合が互いに素 / 依存関係が
ない / 共有状態（スキーマ・設定・グローバル登録簿）を壊し合わない。交差するタスクは後続 wave に
落とす。判断がつかなければ直列にする。並列度の既定上限は 4。

**ワーカーとオーケストレータの責務分担**: ワーカーは自分の所有ファイルとスコープテストのみ扱い、
**コミットも全体 CI も行わない**。wave の全ワーカー完了後（barrier）に、オーケストレータが
境界検証（`git diff --name-only` と所有ファイル集合の突合）→ `CI_CHECK_CMD` → wave 単位の
コミット、の順で実行する。

詳細手順・起動プロンプト雛形・異常系・worktree 隔離は
`.claude/skills/brainstorm/references/parallel-dispatch.md`。ワーカー契約は
`.claude/agents/implementer.md`。

## ループ協議

各タスクは TDD（`coding.md` 参照）+ ループで実行する。CI コマンドは CLAUDE.md の `CI_CHECK_CMD` / `CI_FIX_CMD` を参照（`/harness-init` が検出結果から生成）。

- Red → Green → Refactor → CI のサイクルを回す（最大5回）
- 全チェック通過 → 完了。通過出力を証拠として添える
- 5回使い切った → 残課題を報告して停止
- 同じエラー2回連続 → fixer エージェントに委譲
- チェック出力なしで「完了」報告 / テスト弱体化で通すことは禁止
