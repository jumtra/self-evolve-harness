# デバッグ規約

## 差分診断デバッグ

バグに遭遇したら、まず3〜5個の **反証可能な仮説** を立てる:

1. 各仮説に対して「もしXが原因なら、Yを変えると症状が変わるはず」と予測を立てる
2. 予測を検証する最小限の実験を実行する
3. 予測が外れた仮説は棄却する
4. 残った仮説に対して修正を適用する

闇雲にコードを変えない。仮説→予測→検証のサイクルを回す。

## 3ストライクプロトコル

同じエラーに対する試行回数を追跡する:

| 試行    | アクション                                                                |
| ------- | ------------------------------------------------------------------------- |
| 1回目   | エラーを診断し、原因に基づいて修正する                                    |
| 2回目   | 別のアプローチを試す。同じ操作の繰り返しは禁止                            |
| 3回目   | 前提を疑う。問題の定義自体が間違っていないか再考する                      |
| 3回失敗 | ユーザーにエスカレーションする。「3回試行しましたが解決できません」と報告 |

## サイレント成功・冗長失敗

- 検証が成功した場合: 最小限の出力（「OK」「パス」）
- 検証が失敗した場合: 詳細な情報を出力（エラーメッセージ、スタックトレース、再現手順）

コンテキストを清潔に保つ。成功は静かに、失敗は雄弁に。

## コンテキスト管理

CI/テストの失敗出力をコンテキストに残す際は要約する:

- エラー種別（TypeError, AssertionError 等）
- ファイル:行番号
- 1行のエラーメッセージ

生のスタックトレース全文やテスト出力全文は貼り付けない。要点だけを残して残りは切り捨てる。
