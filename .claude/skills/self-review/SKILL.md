# セルフレビュー

main ブランチからの差分をシニアエンジニアの視点でレビューする。

## コンテキスト収集

- 変更ファイル一覧: !`git diff main...HEAD --name-only`
- 変更差分: !`git diff main...HEAD`
- 変更統計: !`git diff main...HEAD --stat`

## レビュー観点

以下の5観点で差分を精査し、問題を特定する:

### YAGNI

- 現在使われていない抽象化・汎化・引数・フラグがないか
- 「将来使うかも」で追加された処理がないか
- 呼び出し元が1つしかない過度に汎用な関数がないか

### KISS

- より単純な実装で同じ結果が得られる箇所がないか
- 条件分岐・ネスト・制御フローが必要以上に複雑でないか
- クラス・関数・モジュールの過度な細分化がないか

### DRY

- 同じロジックの重複散在、コピー&ペーストによる重複がないか
- 似ているだけで本質的に異なるものを無理に共通化していないか（DRY 過剰）

### Fail Fast

- 不正な引数・状態を関数先頭でガード節しているか
- エラー検出が副作用発生後に後回しになっていないか
- 深いネストにエラー処理が埋もれていないか

### 可読性

- 関数・変数・クラス名が役割を正確に表しているか
- 処理の流れを上から下に追えるか
- 不要なコメント（WHAT を説明するコメント）がないか
- 責務が単一か

### コード品質スコア

Desloppify が利用可能な場合、品質スコアリングを実施する:

1. `desloppify scan --path . --profile ci --no-badge` を実行
2. `desloppify status --json` でスコアを取得
3. スコアをレビュー結果に含める
4. `desloppify` が未インストールの場合はスキップ

## 出力形式

問題ごとに以下を報告し、重篤度の高い順に列挙する:

- **重要度**: Critical / Warning / Info
- **観点**: YAGNI / KISS / DRY / Fail Fast / 可読性
- **場所**: `ファイル:行番号`
- **問題**: 何が問題か
- **修正案**: どう直すべきか

問題がなければ「レビュー通過」と報告する。
