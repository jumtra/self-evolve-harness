# マルチツール同期（/harness-sync）

**正本は常に `.claude/` + `CLAUDE.md` + 記憶層**。他ツール用アーティファクトは
すべてここから再生成できる派生物であり、直接編集しない。

## 対象ツール

| ツール | 生成物 |
|---|---|
| Claude Code | 正本そのもの（`.claude/`・`CLAUDE.md`）を読む。生成なし |
| Codex | ルート `AGENTS.md` の同期ブロックのみ（Codex は AGENTS.md を読む） |
| OpenCode | ルート `AGENTS.md` の同期ブロック + `.opencode/agent/*.md` + `.opencode/command/*.md` |
| その他 AGENTS.md 対応ツール | ルート `AGENTS.md` の同期ブロック |

対象ツールは `command -v codex` / `command -v opencode` で検出し、ユーザーの指定も併用する
（検出されなくても指定されれば生成する）。拡張はこの表に追記する。

## 手順

### 1. 対象ツールの決定

検出結果をユーザーに提示し、生成対象を確認する。

### 2. AGENTS.md 同期ブロック（全対象共通）

ルート `AGENTS.md` に、次のマーカーで囲まれた同期ブロックを作成・更新する:

```markdown
<!-- BEGIN HARNESS-SYNC: このブロックは /harness-sync が .claude/ から生成・上書きする。ブロック外の内容は保持される -->

## このリポジトリのエージェントハーネス

- ワークフロー: コード変更は `/brainstorm` 相当の運用（detail: 要件定義→実装計画→自律実行 /
  simple: 一問一答の確認→実装。スピード重視・任せられるタスクは subagent へ。
  `non-stop` 指定時はヒアリング・承認なしで完了まで止まらない）。定義は `.claude/skills/brainstorm/SKILL.md`
- ルール: `.claude/rules/*.md`（coding / testing / architecture / debugging / workflow / domain / memory）。
  編集対象に該当するルールを必ず読んでから作業する
- CI コマンド: `CLAUDE.md` の「CI コマンド」節が唯一の定義場所
- 記憶: `.claude/rules/memory.md` のバックエンド節に従う
<!-- END HARNESS-SYNC -->
```

- 記憶バックエンドが **file** の場合の記憶行: 「記憶はリポジトリ内 `.agent-memory/`。
  セッション開始時に `.agent-memory/MEMORY.md` を読み、規約に従い保存・検索する」
- **engram** の場合: 「記憶は Engram MCP。このツールにも engram MCP を登録する必要がある」
- ブロック外（既存のサブエージェント規範など）は**絶対に変更しない**。ブロックだけを丸ごと置き換える
- Claude Code は CLAUDE.md を読むため、このブロックは他ツール向け。内容は CLAUDE.md の
  要約とし、詳細を複製しない（齟齬を防ぐため参照リンク中心にする）

### 3. OpenCode agents 生成（OpenCode 対象時）

`.claude/agents/*.md` それぞれを `.opencode/agent/<name>.md` に変換する:

- 先頭に生成物ヘッダを付ける:
  `<!-- GENERATED by /harness-sync. 直接編集禁止。正本: .claude/agents/<name>.md -->`
- frontmatter 変換（OpenCode の agent フォーマット。スキーマは変わりうるため
  最新の OpenCode ドキュメントで確認してから書く）:

| Claude Code | OpenCode |
|---|---|
| `name` | ファイル名が名前になる（frontmatter には書かない） |
| `description` | `description` |
| `model: sonnet 等` | 環境依存のため既定では省略（明示指定があれば変換） |
| `tools: [Read, Bash, ...]` | `tools:` オブジェクトへ対応表で変換（Read→read / Write→write / Edit→edit / Bash→bash / Grep→grep / Glob→glob / WebFetch→webfetch）。対応がない（WebSearch 等）は省略して報告 |
| なし | `mode: subagent` を付与 |

- 本文はそのままコピー。本文中の `.claude/` 参照はリポジトリルートからのパスとして有効なので変換不要
- 削除同期: 正本に無い `<name>.md` が `.opencode/agent/` にあれば生成物ヘッダ付きのものは削除する
  （ヘッダの無い手作りファイルは残して報告）

### 4. OpenCode commands 生成（OpenCode 対象時）

`.claude/skills/*/SKILL.md` それぞれを `.opencode/command/<skill名>.md` に変換する:

- 先頭に生成物ヘッダを付ける:
  `<!-- GENERATED by /harness-sync. 直接編集禁止。正本: .claude/skills/<skill名>/SKILL.md -->`
- frontmatter: `description` をコピー。本体は SKILL.md の frontmatter を除いた全文を
  コマンドのテンプレートとしてコピーする
- 本文中の `references/...` などスキル相対パスは `.claude/skills/<skill名>/references/...` の
  ルート相対パスに書き換える（OpenCode のコマンドにはスキルディレクトリ基準の解決がないため）
- skill と command の意味差: OpenCode のコマンドはプライマリエージェントへのプロンプト展開であり、
  段階的ロードはない（description 前表述の毎ターンコストが発生しない点だけ異なる）

### 5. Codex（対象時）

`AGENTS.md`（手順2）のみ。`AGENTS.md` が正本の決まりごとの入り口として機能する。
追加の生成物は作らない。

### 6. 記憶バックエンドの共有

- **file**: `.agent-memory/` はリポジトリ内のプレーンな Markdown なので変換不要。
  AGENTS.md ブロックと各ツールの指示で「セッション開始時に MEMORY.md を読む」ことを徹底する
  （`.agent-memory/` はコミット対象。`.gitignore` に入っていないことを確認する）
- **engram**: 各ツールにも Engram MCP を登録する必要がある。登録方法はツール固有のため、
  対象ツールの設定ファイル（例: OpenCode は `opencode.json` の mcp 節、Codex は config）への
  追記案を**提案**し、ユーザーの承認後に書き込む（外部設定の自動書き換えはしない）

### 7. 完了報告

```text
## harness-sync 結果

生成: <新規ファイル>
更新: <上書きしたファイル>
削除: <正本消失により消した生成物>
スキップ: <対象外ツール・手作り保護など、理由つき>
```

## 運用ルール

- `.claude/` の agents/skills/rules やメモリバックエンドを変更したら `/harness-sync` を再実行する。
  再実行を忘れると生成物が陳腐化する（`bash .claude/scripts/doctor.sh` が個数差異で警告する）
- 生成物はヘッダで識別し、直接編集は禁止。変換で失われる Claude Code 固有の概念は
  無理に埋めず、スキップ理由を報告する
