# self-evolve-harness v2.0 マルチホスト互換性・実行設計書

- 文書ID: SEH2-HOST-001
- バージョン: 1.3（CLI First改訂・未実装）
- 対象: Claude Code / Google Antigravity（AGY）/ OpenAI Codex / OpenCode
- 基準日: 2026-11-04
- 本文にある機能/設定は**実装案**。各ホストの機能は将来変更されうるため、実装時・CIでバージョン検証する。

## 1. 結論と提供する互換性

**同一のSkill・Prompt・Policy・Evalを、4ホストのネイティブ形式に生成して利用する。** ただし、各ホストのHookイベントと認可方式、Subagent設定、CLI契約は異なるため、すべての内部挙動が同じとは主張しない。CIによる同一の最終合否（outcome parity）を保証することを目標とする。

- **共通の正本（Single Source of Truth）**: `.harness/`下の宣言と共通実行CLI `seh`。`CLAUDE.md`と`AGENTS.md`は正本ではない。
- **HostAdapter**: 共通定義をホスト固有のSkill/Rules/Agents/Hooks/MCP設定に変換し、バージョン差を検査する。
- **AgentRunner**: Managed Modeで許可された公式CLIをsubprocess起動・監視・中断・記録する`CliAgentRunner`。HostAdapterとは別インターフェース。SDK不要。
- **External enforcement**: `seh author` / `seh eval` / Git diff checker / CI required checkで、Hostを問わない最終判定をする。
- **Capability報告**: `NATIVE`, `ADAPTED`, `CI_ONLY`, `UNSUPPORTED`, `UNVERIFIED`を使い分け、欠けた機能を黙って合格扱いしない。
- **全ホストが同じプロセスを通る**: Explore → Decide → Plan → Baseline → Implement → Verify/Repair → Compare → Promote。

## 2. 役割と責務

```text
                       HUMAN / USER TASK
                               |
                    seh work / seh author
                               |
                  H A R N E S S   C O R E
            policy  eval  registry  workflow  memory
                               |
            +------------------+------------------+
            |                                     |
     HostAdapter.render()                 CliAgentRunner.run_once()
     (config & prompt compiler)           (subprocess / JSON events)
            |                                     |
  +---------+---------+----------+         +------+-------+-------+
  |         |         |          |         |      |       |       |
Claude    AGY       Codex    OpenCode    Claude  AGY   Codex  OpenCode
            |                                     |
      Native Host Session                       artifacts
            |                                     |
            +------------------+------------------+
                               |
                         seh eval / CI
                               |
                      PROMOTE or BLOCK
```

**切り離す境界:** `HostAdapter`はMarkdown/JSON/TOMLを生成するだけでCLIプロセスを起動しない。`CliAgentRunner`はPrompt/TaskSpecから公式CLIを起動し、実行イベントを正規化する。`Checker`はホストの回答文を信用せず、ファイル差分、テスト、権限、証拠を再検証する。

## 3. 各ホストの出力形式

| 用途 | Claude Code | Antigravity (AGY) | Codex | OpenCode |
|---|---|---|---|---|
| 継続指示 | `CLAUDE.md`、`.claude/rules/` | `AGENTS.md`/`GEMINI.md`、`.agents/rules/` | `AGENTS.md` | `AGENTS.md` |
| Skill | `.claude/skills/<id>/SKILL.md` | `.agents/skills/<id>/SKILL.md` | `.agents/skills/<id>/SKILL.md` | `.agents/skills/<id>/SKILL.md`（ほかの互換パスも検出） |
| Subagent | `.claude/agents/` | 製品ネイティブのSubagents。定義形式は検証してマッピング | Codexのconfig/agents設定に変換 | `.opencode/agents/` |
| Native Hook | `.claude/settings.json` | `.agents/hooks.json` | 対象バージョンの実装確認。未対応ゲートはCI経由 | `.opencode/plugins/seh-guard.ts`のイベントフック |
| Managed Runner（SDK不要） | `claude -p` | `agy -p`（**利用条件により既定BLOCK**） | `codex exec` | `opencode run` |
| 最終的な安全ゲート | `seh` + CI | `seh` + CI | `seh` + CI | `seh` + CI |

注：AGYにはApp、CLI、IDEなど複数の動作面がある。v2はAGYを単一互換性フラグとして扱わず、`antigravity.app`、`antigravity.cli`、`antigravity.ide`のうち実際にインストールされた面を検出し、Skill/Hookのサポートを別途確認する。`AGENTS.md`の共用は可能だが、各ホストの命令優先順位が等しいと仮定しない。

### 3.1 パスの衝突と重複防止

OpenCodeは`.agents/skills`と`.claude/skills`の両方を探索する場合がある。そのため、Claude CodeとOpenCodeを同じrepoで有効化する際は**同名のSkillが複数定義として現れないことを実際に検証する**。

- `seh sync`はファイルを無条件に複写しない。出力ターゲットに「共有」「複写」「リンク」「抑止」を計画し、選択したホストの実測Discovery結果に応じて生成。
- `seh doctor --hosts`で各ホストが見つける論理Skill名一覧、出力内容hash、実効権限を収集。
- 同一Skillの重複読み込みや異なる権限になりうる場合、`COLLISION`と報告して昇格を止める（未検証の重複解決を仮定しない）。
- `CLAUDE.md`・`AGENTS.md`内には共通ポリシーへの短い参照だけ入れ、長いSkill本文は入れない。

## 4. Canonical source と生成管理

```text
<repo>/
├── .harness/
│   ├── config.toml                 # 設定正本 / enabled hosts
│   ├── spec/                       # Host非依存の入力定義
│   │   ├── instructions/core.yaml  # 共通の継続方針
│   │   ├── agents/*.yaml           # ロール、ツール権限、制約
│   │   ├── skills/<id>/            # 論理Skill定義、references、scripts
│   │   │   └── SKILL.md
│   │   └── workflows/*.yaml        # Eval/修正DAG
│   ├── evals/                      # 共通Fixture/期待値
│   ├── authoring/                  # AuthoringRecord と証拠の参照
│   ├── ownership.json              # 管理対象hashとホスト差分
│   └── generated.lock.json         # 出力対応バージョンとCapability
├── .claude/                        # Claude用生成物
├── .agents/                        # AGY, Codex, OpenCode等の共有Skills/AGY hooks
├── .opencode/                      # OpenCode専用Agent/Plugin
├── .codex/                         # Codex設定（必要時）
├── CLAUDE.md                       # Claude用短い生成ブロック
└── AGENTS.md                       # Codex/OpenCode/AGY用短い生成ブロック
```

`seh sync`は*正本→ホスト生成物*の一方向。各ホスト上でユーザーが編集した出力がある場合は、`ownership.json`のdigestと照合し三者差分を提示して承認を求める。手編集したSkill/Rulesは勝手に削除しない。

## 5. HostAdapter / CliAgentRunner 契約

```python
class HostAdapter(Protocol):
    def probe(self, installation: HostInstall) -> CapabilityReport: ...
    def render(self, source: CanonicalSpec, ctx: RenderContext) -> GeneratedPlan: ...
    def lint(self, plan: GeneratedPlan) -> list[Diagnostic]: ...
    def discover(self, workspace: Path) -> DiscoveryReport: ...

class CliAgentRunner(Protocol):
    def probe(self) -> RuntimeCapabilityReport: ...
    async def run_once(self, task: WorkUnit, ctx: RunContext) -> RunResult: ...
    async def cancel(self, run_id: str) -> CancelResult: ...
```

Coreの`RunResult`は `run_id, host, command_digest, exit_code, terminal_state, answer, usage?, events, artifacts, evidence_refs, error_code?` を持つ。CLIごとのstdout JSON/JSONLを変換する。ストリームはCLIに対応する場合の任意イベント供給、session resumeも任意Capabilityであり、全ホストに強制しない。

**安全性**: プロンプトをShell文字列連結しない。CLIは`create_subprocess_exec`にargv配列で渡し、cwd/worktreeとenvを限定。タイムアウト後に子プロセスを確実に停止し、ファイル範囲と検査結果を検証する。CLI内部Toolを完全に仲介できると誤認しない。

```toml
[hosts]
enabled = ["claude", "antigravity", "codex", "opencode"]

[runtime]
mode = "native"           # native or managed
backend = "cli"           # CLIが唯一の標準実行backend。SDK不要
provider = "auto"         # claude, codex, opencode, antigravityは利用条件次第

[authoring]
policy = "required"
require_eval_for_behavior_change = true
required_hosts = "active" # 使用ホストを明示。4ホストFULLはall requiredがPASSした場合のみ
require_ci_for_promote = true

[hosts.antigravity]
surface = "auto"          # app, cli, ide, auto
managed_cli = "disabled"  # 利用規約/契約上の使用可能性の確認が必要
```

**AGY利用条件**: Google公式FAQは、個人向けプランで`agy -p`を第三者コーディングエージェント/アプリからラップすることをサポート対象外と説明している。したがって`managed_cli=disabled`が既定。設定・Skillの生成は別途行えるが、CLI自動実行は適切な契約・許可が確認できた環境だけで明示的に有効化できる。アカウント切替や禁止された接続方式を自動化しない。

## 6. Skill・Prompt規約の4ホスト強制

1. `seh author classify`は4ホストのRule/Skill/Agent/Hook構成ファイルを監視する。旧来のClaudeのみ対象では不十分。
2. `seh author plan`はPrompt/Skillの配置先を**ホスト非依存**で判定。`CLAUDE.md`固定の選択肢を`persistent_instructions`という抽象要素へ置き換える。
3. `seh author lint`は正本を検査し、続けて**各ホスト別frontmatter/権限/パス**を検査。
4. `seh author eval --hosts enabled`は同じFixtureのpositive/negative trigger・outcome・permission regressionを対応ホストのfresh sessionで実行。
5. モデルやサービス契約の都合で自動E2Eを実行できないホストは`BLOCKED_NO_EVAL`または`UNVERIFIED`。ユーザーが承認済みの**限定的な代替評価**を定義した場合のみ例外を記録し、フル互換と表示しない。
6. `seh author promote`はCIゲートと必須ホストのEvalがPASSした場合だけ昇格。未知のCapabilityや未検証結果をPASSに変えない。

### 6.1 Native mode と Managed mode

- **Native**: Host標準のSkill/Rules/Hooks等でユーザーが直接作業。実行中の介入保証はHost依存。`seh author`とCIは共通。
- **Managed**: Harnessが`CliAgentRunner`を通じて公式CLIの1ユニットを起動し、write allowlist、予算、DAG、checker、repair、checkpoint、Promoteを外側で中央制御。AGYは利用条件により`POLICY_BLOCKED`。別Hostへ黙って振替しない。
- **同等性の定義**: `same policy + same eval fixtures + same final gate + normalized evidence`。回答文面・モデル内部動作の完全一致は求めない。

## 7. Hostごとの検証マトリクス

| 検証項目 | Claude | AGY | Codex | OpenCode |
|---|---|---|---|---|
| 共通ポリシーのロード | MUST | MUST | MUST | MUST |
| 2つの公開SkillのDiscovery | MUST | MUST | MUST | MUST |
| Agentの読み取り専用設定 | MUST | MUST/差分を報告 | MUST/差分を報告 | MUST |
| HookまたはPluginでの事前防御 | サポート時MUST | サポート時MUST | 無理ならCI_ONLY | サポート時MUST |
| Authoring Gateの変更検出 | MUST | MUST | MUST | MUST |
| Evalのfresh-session実行 | MUST | MUST | MUST | MUST |
| 失敗時のRepair+境界制御 | Managed Runner利用時 | 同左 | 同左 | 同左 |
| CIが証拠不足の昇格を阻止 | MUST | MUST | MUST | MUST |
| Skillの重複Discoveryなし | MUST | MUST | MUST | MUST |

判定結果は`FULL`, `PARTIAL`, `BLOCKED`, `UNSUPPORTED`としてホスト単位に報告。CLIの認証がない等の環境依存条件は`BLOCKED`と区別し、成功率の分母から勝手に除外しない。

## 9. 検証コマンド例（すべて新規実装予定）

```bash
seh init --hosts claude,antigravity,codex,opencode --plan
seh sync --hosts all --plan
seh sync --hosts all --apply
seh doctor --hosts all --format json
seh author lint --changed --hosts all
seh author eval --record .harness/authoring/AUTH-001.json --hosts all --fresh
seh eval compare --across-hosts --fixture-set prompt-skill-baseline
seh author promote --record .harness/authoring/AUTH-001.json
```

**不変条件:** ひとつのホストだけテストが通ったからといって全ホストを`PASS`にしない。Host Adapterごとの設定差とRunnerのイベント取得可否を`compatibility.json`に保持し、4ホストが揃わない場合は「4環境完全互換」を名乗らない。

## 11. v1.3修正点（CLI First / SDK Optional）

`managed`はSDKを呼ぶのではなく、**公式CLIを外側から実行するPythonワークフロー**。対応フラグ、JSON出力、終了状態、usage、認証、危険操作の権限モードは4ホストで異なる。CLI Runnerを4種類に分け、共通Coreにベンダー固有オプションを持ち込まない。

| Host | 標準コマンド | JSON系出力 | Managed実行の扱い |
|---|---|---|---|
| Claude Code | `claude -p` | `--output-format json`または`stream-json` | 対応。`--bare`を使用するとSkill等を読み込まないためEval時は注意 |
| Codex | `codex exec` | `--json`（JSONL）、`--output-schema` | 対応。`--sandbox`権限とプロジェクトconfigをprobe |
| OpenCode | `opencode run` | `--format json`（イベント列） | 対応。Plugin/権限/Sessionをバージョン別に検査 |
| AGY | `agy -p` | `--output-format json/stream-json` | **第三者ラッピングの利用条件により既定POLICY_BLOCKED** |

Managedの「FULL」判定には、実装可能性だけでなく**契約上の使用可能性、実機のE2E成功、独立checker合格**が必要。AGYを含む4ホストFULLを標準で自動宣言しない。
