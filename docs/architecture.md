# アーキテクチャ

v2 の正本は `.harness/spec/` と設定です。ホストごとの形式への描画、差分計画、適用を分離し、管理外の利用者の記述を保持します。契約と Schema を基礎に、Policy、実行、評価、CLI が上位から依存します。詳細と実装順は [実装計画](specs/2026-11-04-v2-harness-plan.md) を参照してください。

設計の中心は、小さな常時指示と必要時に読む詳細、明示的な権限、作業ごとの責任分担、決定論的な検証、証拠を伴う完了判定です。これらは既存の設計リファレンスに記録した段階的な情報開示、独立検証、保護境界の考えを引き継ぎます。

Native はホストの機能で実行し、Hook と CI で確認します。Managed は公式 CLI を独立した worktree から実行し、DAG、予算、試行、検査と checkpoint を管理する設計です。CLI の内部で行われる個々の操作を完全に仲介できる保証はありません。最終的な強制には必須 CI と branch protection が必要です。実行モードごとの制約は [実行モード](modes.md) にあります。

候補の生成と検証、昇格は別の段階です。Hook や権限などの変更は承認と評価が必要です。現段階では Managed と自己進化の統合は開発中であり、設計どおりの保証が実機で確立したことを意味しません。
