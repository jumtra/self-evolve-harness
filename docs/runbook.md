# 運用手順

## 導入前

作業中の変更を保存し、`seh init --hosts all --plan` の生成内容と競合を確認します。適用は利用者が対話端末から行います。移行を伴う場合は [移行手順](migration-v1-to-v2.md) に従い、snapshot ID を保管します。

## 診断

`seh doctor` で設定と環境を、`seh doctor --context` で常時読み込む Context を確認します。ホスト互換性診断は開発中です。コマンドが失敗したときはエラーの対象と終了コードを確認し、設定や生成物を手動で上書きする前に Git 差分を保存してください。

## 復旧

移行時の変更を戻す場合は `seh migrate rollback <snapshot-id>` を実行し、表示された復元ファイルと Git 差分を確認します。snapshot の対象外の変更は別途保全したバックアップから復元してください。同期や初期化の失敗時は出力されたエラーと差分を確認し、再適用前に対象の状態を確認します。

## 安全境界

未承認の高リスク操作を無人で実行しないでください。Native の Hook はすべての編集経路を遮断できません。必須 CI や branch protection がない場合、最終ゲートは `NOT_ENFORCED` です。外部サービスやツールの認証情報はログや証拠に記録しないでください。
