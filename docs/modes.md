# Native と Managed の実行モード

Native では利用者がホストの Skill、Rules、Hooks を使って直接作業します。実行中に介入できる範囲はホストの機能に依存します。Managed では harness が公式 CLI を起動し、依存関係、並列数、予算、書き込み範囲、検査、修復、チェックポイントと昇格を管理します。

両モードは同じ方針、評価 fixture、最終ゲートと正規化された証拠を使います。Native の実行中に Managed と同じ制御が強制されるという保証はありません。独立した評価と CI は両方に必要です。

## 最終ゲートの強制

Hook は早期検出に役立ちますが、ホスト外での編集を常に防ぐことはできません。GitHub の必須 CI チェックと branch protection を最終強制点にしてください。必須チェックが設定されていない場合は `NOT_ENFORCED` と表示し、CI による可視化だけでは強制を保証しません。

## Google Antigravity

Antigravity の設定や Skill は生成できます。Managed CLI の第三者ツールによる実行は、利用条件と利用資格の確認が必要なため既定では `POLICY_BLOCKED` です。許可が確認できた環境でのみ明示的に有効化してください。ブロックされたタスクを他のホストへ自動的に振り替えません。App、CLI、IDE の対応状況はそれぞれ診断します。

評価できないホストは `BLOCKED_NO_EVAL` または `UNVERIFIED` として記録し、未検証のまま完全対応とは扱いません。
