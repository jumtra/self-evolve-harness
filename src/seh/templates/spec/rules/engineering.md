# 実装規約

## TDD

- Red: 期待する振る舞いのテストを先に書き、**失敗を確認**する
- Green: 通す最小限の実装だけを書く
- Refactor: テストが通ったまま整理する。振る舞いは変えない

## 関数設計

- 単一責任。1関数1目的
- 早期リターンでネストを減らす
- 副作用を最小化し、純粋関数を優先する

## エラーハンドリング

- Fail Fast: 不正な引数・状態は関数先頭でガードする
- 独自の例外 / エラー型を定義して使う

## 冪等性

- 再実行しても同じ最終状態に到達する設計にする
- ファイル書込は一時ファイル + rename（原子的書込）
- 既存リソースの作成はエラーにせず、スキップか上書きにする

## Linter / Formatter 規律

- linter・formatter の設定を変えない
- 抑制コメント（`noqa` / `type: ignore` / `eslint-disable` 等）を追加しない
- 指摘はコードを直して解消する。本当に必要ならユーザーに相談する

## スコープ規律

範囲外の改善点はその場で直さず、報告に記録する。

```
NOTICED BUT NOT TOUCHING:
- <ファイル:行> <改善内容>
```
